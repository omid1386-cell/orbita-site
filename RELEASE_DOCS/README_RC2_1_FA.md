# ORBITA — راهنمای نسخه RC2.1 (نامزد انتشار)

این بسته **تمام اصلاحات گام‌های ۱ تا ۹ و اصلاحات قرارداد داده زنده** را به صورت یکپارچه دارد.
نسبت به RC2، فقط اطلاعات انتشار، فهرست هش‌ها و راهنمای نصب اصلاح شده‌اند؛ فایل‌های اجرایی RC2 بدون تغییرند.

## هشدارهای پیش از بارگذاری

- به هیچ وجه ZIP را به‌عنوان یک فایل تنها در GitHub قرار ندهید؛ پس از استخراج، فایل‌های اجرایی را به مسیرهای اصلی مخزن **شاخه آزمایشی** منتقل کنید.
- **RC1 و PATCH جداگانه دیگر لازم نیستند**. برای سورسی که گام‌های قبلی را نصب ندارد، فقط RC2.1 کافی است.
- اگر مخزن بعد از تهیه سورس اصلی ویرایش شده، فایل‌های index.html و assets/css/app.css را بدون مقایسه/ادغام جایگزین نکنید.
- فایل‌های RELEASE_DOCS و LIVE_VALIDATION مستندات‌اند و قرار نیست جای فایل‌های اجرایی سایت قرار گیرند.
- دو GitHub Actions جدید داخل `.github/workflows` دارای زمان‌بندی خودکار و اجازه `contents: write` هستند؛ بعد از قرارگرفتن روی شاخه پیش‌فرض می‌توانند داده‌های JSON را خودکار به مخزن Commit کنند. ابتدا روی شاخه آزمایشی بررسی شوند؛ پیش از انتشار روی شاخه اصلی سیاست اجرای خودکار تنظیم شود.
- در snapshots بانک جهانی پرتاب و فرود هنوز `awaiting_first_successful_sync` ثبت شده است. اعتبارسنجی دریافت کل صفحات شبکه‌ای انجام نشده و پوشش جهانی فرودها محدود است.
- آزمون واقعی روی محیط منتشرشده نیز انجام نشده است.

## تأیید فایل‌های بسته

از پوشه استخراج‌شده:

```bash
python RELEASE_DOCS/verify_release.py
```

بعد از ایجاد نسخه آزمایشیِ سورس، می‌توانید از `--target` و `--mode before` و `after` مطابق راهنمای گام نهم استفاده کنید. این اسکریپت صرفاً تطبیق هش را انجام می‌دهد و اصلاحات را اعمال نمی‌کند.

## آزمون فقط‌خواندنی داده زنده

```bash
python tools/validate_live_global_sources.py --launch-only --report launch_live_check.json
# در ساعت جداگانه با توجه به سهمیه منبع
python tools/validate_live_global_sources.py --landing-only --report landing_live_check.json
```

اطلاعات واقعی تا انجام این اعتبارسنجی نباید به عنوان «پوشش جهانی تأییدشده» معرفی شوند.
