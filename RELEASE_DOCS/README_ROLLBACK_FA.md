# راهنمای بازگشت به نسخه اصلی ORBITA (بسته گام نهم)

**این بسته برای مواقعی است که تغییرات گام‌های ۱ تا ۸ روی نسخه اصلی سه‌پارته نصب شده‌اند و لازم است به وضعیت قبل برگردیم.** هیچ عملی در زمان تهیه آن اجرا نشده است.

## راهکار اول، ترجیحی: Git revert

اگر تغییرات در یک کامیت مجزا به GitHub اعمال شدند، امن‌ترین روش، بازگردانی همان کامیت از طریق GitHub یا `git revert` است. این روش سابقه تغییر را حفظ می‌کند.

## راهکار دوم، بازگشت دستی

۱. قبل از هر کار، از وضعیت فعلی مخزن و به‌ویژه دو فایل داده `data/upcoming_global.json` و `data/upcoming_global_landings.json` نسخه پشتیبان تهیه کنید؛ شاید پس از نصب به‌طور خودکار تغییر کرده باشند.

۲. فایل‌های `baseline/index.html` و `baseline/assets/css/app.css` این ZIP را در همان مسیر اصلی مخزن جایگزین کنید. این‌ها **عین نسخه اولیه ارسالی کاربر** هستند.

۳. فایل‌های جدید فهرست‌شده در `new_paths.txt` تنها در صورتی قابل حذف‌اند که توسط قابلیت دیگری استفاده نشده باشند؛ خودکار حذف نمی‌شوند. اگر در طول کار تغییر کرده باشند، پیش از حذف از داده‌ها پشتیبان بگیرید.

۴. دو Workflow جدید را هم در صورت تصمیم به بازگشت حذف/غیرفعال کنید تا دوباره داده‌های جدید ایجاد نشوند.

۵. اجرا و نسخه‌برداری را پس از بازگشت تست کنید.

**هشدار:** این بسته، بازگشت کامل به هر نسخه دلخواه GitHub را تضمین نمی‌کند. فقط با نسخه اصلی سه‌پارته‌ای که برای ساخت این بسته دریافت شد سازگار است؛ اگر نسخه آنلاین متفاوت است، ابتدا تاریخچه Git را بررسی کنید.
