# راهنمای نصب بسته تجمیعی ORBITA در GitHub (تا گام ۴ بانک رسانه)

## مهم: نوع بسته
این ZIP یک **بسته افزایشی/جایگزینی فایل (overlay)** برای مخزن کامل و موجود ORBITA است، نه کپی مستقل از کل سایت. محتویات ZIP با مسیرهای ریشه مخزن (`index.html`، `assets/...`، `data/...`، `tests/...` و ...) هماهنگ‌اند. **فایل ZIP را به‌تنهایی در GitHub قرار ندهید.**

نسخه کد این بسته از RC2.1 (رویدادهای پرتاب و فرود) + گام دوم و سوم بانک رسانه + گام چهارم در چهار نوبت گردآوری رسانه ساخته شده است؛ برای نصب آن به ZIPهای مراحل قبلی احتیاج نیست.

## دستور نصب کنترل‌شده

1. از شاخه اصلی و فایل‌های فعلی مخزن بکاپ و یک شاخه جدید (مثل `feature/orbita-media`) تهیه کنید. چیزی را از مخزن پاک نکنید.
2. ZIP را استخراج کنید. محتویات داخل آن را با حفظ همین ساختار پوشه‌ها در **ریشه پروژه ORBITA** کپی و ادغام کنید؛ پوشه `ORBITA` جدید/دوبل ایجاد نکنید.
3. مخصوصاً `index.html`، `assets/js/app.js` و `assets/css/app.css` را با نسخه کنونی GitHub تطبیق دهید. این بسته از سورس ارسالی کاربر ساخته شده و تغییرات مستقل و جدیدتر GitHub را خودکار با هم merge نمی‌کند.
4. پس از ادغام، از **ریشه کل پروژه** اجرا کنید:

```bash
python RELEASE_DOCS/verify_media_overlay.py
python -m unittest discover -s tests -p 'test_*.py'
python -m unittest discover -s tools -p 'test_*.py'
node --test tests/*.test.cjs
```

5. ابتدا در شاخه آزمایشی از بازشدن نقشه و ۱۴ نوع شناسنامه، وجود گالری، تصاویر تأییدشده و لینک ویدئوها اطمینان حاصل کنید. تست مرورگر محلی جای تست نهایی Render را نمی‌گیرد.
6. ویدئوهای جدید فقط به صفحه ناشر لینک دارند؛ خود فایل ویدئو مجدداً میزبانی نشده است. آدرس‌های ویدئو/تصویر ممکن است در طول زمان از دسترس خارج شوند. نمایش ویدئوها برای کاربران باید از داخل مرورگر واقعی آزمایش شود.
7. تا قبل از تأیید، این نسخه را مستقیم جایگزین شاخه اصلی یا محیط عمومی نکنید.

## هشدار مهم درباره GitHub Actions
دو گردش‌کار `.github/workflows/refresh-global-launches.yml` و `refresh-global-landings.yml` به‌صورت زمان‌بندی‌شده فعال و دارای اجازه `contents: write` هستند. **اگر این فایل‌ها به شاخه پیش‌فرض بروند، ممکن است با اولین اجرای مجاز داده‌های JSON را خودکار به مخزن Commit کنند.** پیش از ادغام به شاخه اصلی، زمان‌بندی/دسترسی نوشتن و سهمیه سرویس را بررسی کنید؛ می‌توانید این دو فایل را برای مرحله نخست از Commit کنار بگذارید و بعد از تأیید فعال کنید.

## محدوده گام چهارم (اطلاعات تاریخی بسته پایه)
- ۴۲۰ شناسنامه و ۱۴ دسته از نظر قابلیت بانک رسانه پشتیبانی می‌شوند.
- از ۹۶ سازمان فضایی، ۵۱ سازمان دست‌کم یک رسانه تأییدشده دارند؛ ۴۵ سازمان هنوز فاقد رسانه تأییدشده‌اند.
- در نوبت حاضر ۱۹ رسانه قابل نمایش اضافه شد (۲ عکس با مجوز مشخص و ۱۷ پیوند ویدئو) و یک لینک نامطمئن رومانی به وضعیت بررسی‌نشده منتقل شد.
- در کل بانک ۷۷ رسانه تأییدشده و ۴ رسانه نامزدِ ممنوع از نمایش عمومی ثبت شده‌اند.
- در زمان تدوین این بخش، گام‌های رسانه‌ای ۵ تا ۹ هنوز انجام نشده بودند؛ این بسته **نسخه نهایی کل پروژه رسانه‌ای نیست**.
- دریافت زنده جهانی پرتاب‌ها/فرودها و تست انتشار روی Render هنوز کامل نشده‌اند.

## بازگشت از تغییرات
قبل از نصب از پروژه یک Commit/Tag تهیه کنید. در صورت اشکال، با `git revert` یا بازگرداندن شاخه/Commit قبل از نصب، فایل‌های جایگزین‌شده را به وضع قبلی برگردانید و فایل‌های جدید این بسته را حذف کنید. صرفاً حذف `catalog.v1.json` کافی نیست، زیرا رابط و فایل‌های JavaScript/CSS نیز اضافه یا تغییر کرده‌اند.

## کنترل صحت فایل‌ها

```bash
python RELEASE_DOCS/verify_media_overlay.py
```

این برنامه هش فایل‌های **همین بسته** را بررسی می‌کند. موفقیت آن به معنای تأیید عملکرد سایت آنلاین، اجازه پخش ویدئوها یا پوشش کامل همه سازمان‌ها نیست.
