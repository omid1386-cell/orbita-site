# رسپهر (RASPEHR) — راهنمای انتشار بستهٔ اتصال گوگل مپس و گوگل ارث
**نسخه تحویل:** V16-RC1 · ۲۶ نوامبر ۲۰۲۶ · بستهٔ مخصوص **مخزن موجود** `omid1386-cell/orbita-site`

> این بسته فقط فایل‌هایی را که لازم است به مخزن موجود افزوده یا جایگزین شوند در `UPLOAD_TO_REPO_ROOT/` دارد. **فایل ZIP را مستقیم در GitHub آپلود نکنید.** آن را استخراج کنید و **محتویات** پوشه را به ریشه مخزن کپی کنید. هیچ فایل دیگری را پاک نکنید. برای اجرای این مرحله نیازی به دانلود فونت‌ها یا جایگزینی تصاویر پیشین نیست.

## نتیجه‌ای که باید پس از انتشار مشاهده شود
در سایت رسپهر (`index.html`) با ورود به **«نمای سه‌بعدی»** و انتخاب یکی از ۴۲۰ المان، شناسنامه باز می‌شود. در منوی بازشوندهٔ **«مشاهده در نقشه‌های دیگر»** سه گزینه قرار دارد:
1. «مشاهده موقعیت در گوگل مپس»؛ لینک مبتنی بر مختصات.
2. «نمای ماهواره‌ای محیط در گوگل مپس»؛ نمای ماهواره‌ای با بزرگ‌نمایی اولیه متناسب با دسته.
3. «کاوش در گوگل ارث · لینک مستقیم آزمایشی»؛ لینک دوربین گوگل ارث، تولیدشده از مختصات.

مجموع پیوندها **۱۲۶۰ مورد** است (۴۲۰+۴۲۰+۴۲۰). پنج پیوند گوگل ارث به‌گفتهٔ صاحب پروژه در پایلوت موفق بوده‌اند، اما **۴۱۵ پیوند دیگر بازشدن زندهٔ مستقل ندارند**. قالب دوربین گوگل ارث API عمومی تضمین‌شده نیست؛ خطای ۴۰۳ یا عدم بارگذاری سرویس گوگل ارث در بعضی شبکه‌ها ممکن است رخ دهد. نبود پوشش سه‌بعدی یا پانوراما نباید به‌عنوان نقص فایل رسپهر تلقی شود.

## مسیر ایمن و پیشنهادی انتشار با GitHub Desktop
1. از مخزن اصلی `https://github.com/omid1386-cell/orbita-site` یک **نسخه پشتیبان یا شاخه موقت** بگیرید. بهتر است قبل از عملیات، SHA آخرین commit شاخه `main` را ثبت کنید. اگر سایت به‌صورت خودکار از `main` منتشر می‌شود، **تا قبل از کنترل نهایی با main کار نکنید**.
2. GitHub Desktop را باز کنید، مخزن را Clone کنید و شاخه جدیدی مانند `release/raspehr-v16-links` بسازید.
3. بستهٔ `RASPEHR_V16_RC1_UPLOAD_TO_EXISTING_GITHUB_2026-11-26.zip` را روی رایانه استخراج کنید.
4. **فقط محتویات پوشهٔ `UPLOAD_TO_REPO_ROOT/`** را در **ریشهٔ مخزن Cloneشده** کپی کنید (کنار `index.html`). مسیرهای پوشه‌ای را حفظ کنید. پوشهٔ `UPLOAD_TO_REPO_ROOT` نباید خودش به مخزن وارد شود.
5. در GitHub Desktop تغییرات را بررسی کنید. **اگر در فایل‌های موجود تغییراتی مستقل از بستهٔ این پروژه داشته‌اید، جایگزینی کورکورانه نکنید**؛ اختلاف‌ها را بررسی و ادغام کنید. بقیه فایل‌ها، از جمله تصاویر و داده‌های جاری سایت، باید حفظ شوند.
6. در ریشه مخزن این دستور را برای بررسی یکپارچگی اجرا کنید:
   `python RELEASE_DOCS/RASPEHR_V16_DEPLOY/verify_release.py`
   انتظار: تمام کنترل‌ها PASS. سپس:
   `node --test raspehr-3d/tests/*.test.cjs`
   انتظار: **۷۰ آزمون موفق**. آزمون کامل دو‌بعدی فعلا دارای **۴۷ شکست شناخته‌شده** است؛ آن را پنهان یا موفق گزارش نکنید.
7. تغییرات را در همان شاخه Commit و Push کنید؛ یک Pull Request به `main` ایجاد کنید. برای بررسی درخواست ادغام، `RELEASE_MANIFEST.json` و گزارش QA را مرجع قرار دهید.
8. **پس از تصمیم برای انتشار عمومی**، شاخه را در main ادغام کنید. این کار ممکن است GitHub Pages و Render را (اگر Auto Deploy روشن باشد) بلافاصله به‌روزرسانی کند.

## استفاده از Git در خط فرمان (اختیاری)
```bash
git clone https://github.com/omid1386-cell/orbita-site.git
cd orbita-site
git switch -c release/raspehr-v16-links
# پس از استخراج بسته، محتویات UPLOAD_TO_REPO_ROOT را روی همین پوشه کپی کنید
python RELEASE_DOCS/RASPEHR_V16_DEPLOY/verify_release.py
node --test raspehr-3d/tests/*.test.cjs
git status --short
git diff --check
git add -A
git commit -m "RASPEHR V16: external Google location links"
git push -u origin release/raspehr-v16-links
```
**توضیح:** اجرای کد بالا نمونه است؛ این دستورات از طرف من روی مخزن یا سایت اجرا نشده‌اند.

## Render — اشتباه رایج در این مخزن
- وب‌سایت اصلی **Static Site** است: `index.html` و `raspehr-3d/index.html` نیازی به build ندارند.
- فایل `render.yaml` موجود **فقط سرویس جداگانهٔ `orbita-report-api`** را تعریف می‌کند؛ برای فعال‌سازی خود نقشه آن را به‌اشتباه به‌عنوان Blueprint سایت اصلی به کار نبرید.
- اگر وب‌سایت فعلی در Render به GitHub متصل است، **همان Static Site موجود** و شاخهٔ انتشار آن را نگه دارید. تنظیمات رایج برای سایتی با ریشه این مخزن: Root Directory خالی، Build Command یک دستور سادهٔ بدون build (مثلا `echo static`)، Publish Directory برابر `.`؛ **پیش از هر تغییر به تنظیمات، آن‌ها را با سرویس فعلی مقایسه کنید**.
- اگر Auto Deploy خاموش است، از بخش Deploys سرویس اصلی یک Deploy برای commit جدید انجام دهید. هیچ نیازی به تغییر متغیرهای محرمانه API نیست.
- اگر از GitHub Pages استفاده می‌کنید، workflow فعلی `.github/workflows/pages.yml` از **ریشه پروژه** فایل‌ها را انتشار می‌دهد. مسیر پایه نیز باید با محل انتشار واقعی تطبیق داشته باشد.

## پنج آزمون ضروری بعد از انتشار
1. آدرس اصلی رسپهر را باز کنید، نقشه دوبعدی و سپس «نمای سه‌بعدی» را بررسی کنید. اگر ۳D بارگذاری نشد، ابتدا منابع شبکه/بافت/وب‌جی‌ال را در مرورگر بررسی کنید.
2. شناسنامهٔ **استاربیس** (پایگاه پرتاب) را باز کرده، منوی نقشه‌های دیگر را بررسی کنید: مپس، نمای ماهواره‌ای و گوگل ارث باید سه لینک مجزا باشند.
3. شناسنامهٔ **راکت‌لب** (شرکت) و **باند فرود کندی** (بازیابی) را هم آزمایش کنید؛ پس از برگشت از تب خارجی، انتخاب و فیلتر رسپهر باید باقی بماند.
4. روی موبایل، منوی شناسنامه باز شود و لینک‌ها زیر پنل بریده یا پنهان نباشند. سپس بازگشت به حالت دوبعدی را بررسی کنید.
5. در DevTools/Network مرورگر، پاسخ موفق برای `raspehr-3d/data/external-links-v1.json`، `raspehr-3d/assets/js/external-map-links-v1.js` و CSS مرتبط را بررسی کنید. اگر پس از انتشار رابط قدیمی بود، یک بار Hard Refresh انجام دهید. تنها ارجاع‌های دو فایل 3D در این انتشار شناسه کش تازه گرفته‌اند.

## محدودیت‌ها و شرط پذیرش
- **آزمون آنلاین روی نسخه منتشرشده هنوز انجام نشده است.** قبل از پذیرش نهایی، پنج آزمون فوق باید روی سایت واقعی موفق شوند.
- **۴۷ شکست شناخته‌شدهٔ مجموعهٔ ۱۹۰ آزمون دوبعدی** باقی‌اند. این بسته آن‌ها را حل نکرده است؛ تصمیم درباره اثر عملی آن‌ها باید با آزمون پس از انتشار گرفته شود.
- **۸۸۷ فایل محافظت‌شده، از جمله ۴۸ عکس پایگاه پرتاب، در نسخه V16-RC1 تغییر نکرده‌اند.** فایل‌های اصلی داده و ورودی سایت نیز در این انتشار اصلاح نشده‌اند.
- برخی مختصات **تقریبی/مرجع** هستند و نشانی دقیق ساختمان را نشان نمی‌دهند؛ ۳۹۹ رکورد از نظر دقت مکانی هنوز تأیید مستقل ندارند. نمایش پنل از نظر داده بر اساس ثبت فعلی رسپهر است.
- تصاویر و ابزار تاریخی KML موجود در فایل‌های QA به معنای فعال‌سازی راهکار KML نیستند؛ این راهکار بنا به تصمیم کاربر خارج از قابلیت عمومی است.

## بازگشت ایمن (Rollback)
- شناسه commit قبل از ادغام را ثبت کنید.
- در صورت اختلال اساسی، در GitHub Desktop یا Git یک **commit برگشت‌دهنده (revert)** روی شاخه جدید بسازید و از طریق Pull Request به main برگردانید. **Force Push / Reset شاخه main نکنید**؛ زیرا ممکن است تغییرات مستقل، داده‌های تازهٔ پرتاب یا فرود و commitهای دیگران را از بین ببرد.
- بعد از Revert، از Render نسخه برگشته را دوباره Deploy کنید (یا اجازه دهید Auto Deploy اجرا شود).
- اگر فقط گوگل ارث در شبکه ایران باز نشد، لزوما نیازی به Rollback کل سایت نیست: مپس و نمای ماهواره‌ای همچنان گزینه‌های مستقل‌اند.

**خلاصه:** این بسته برای اعمال **روی مخزن موجود** آماده است؛ جایگزین همهٔ سورس موجود یا تأییدیهٔ تست زندهٔ Google Earth نیست. انتشار واقعی فقط پس از اقدام صاحب مخزن رخ می‌دهد.
