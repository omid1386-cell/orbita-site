# دریافت گزارش‌های ORBITA

این پوشه یک سرویس کوچک سمت‌سرور برای دریافت دو نوع گزارش جداگانه دارد: ایراد فنی و اختلاف علمی/داده‌ای. گزارش علمی شامل رکورد، فیلد، مقدار فعلی، مقدار پیشنهادی و پیوند منبع است. سرویس گزارش‌ها را فقط به نشانی ثابتِ تنظیم‌شده در سرور ایمیل می‌کند؛ هیچ گزارشی داده‌های سایت را تغییر نمی‌دهد و هر اصلاحی باید پس از بررسی و تأیید انسانی انجام شود.

## مسیر ارسال و حریم خصوصی

- سایت اصلی ایستا می‌ماند؛ این API باید به‌عنوان **Web Service** جداگانه در Render اجرا شود.
- ارسال ایمیل با API رسمی Resend روی HTTPS انجام می‌شود، نه SMTP. کلید فقط در متغیر محیطی سرویس Render می‌ماند و هرگز در مرورگر قرار نمی‌گیرد.
- فرم فقط هنگام فشردن «ارسال» با API تماس می‌گیرد. گزارش و ایمیل اختیاری تماس به Resend و سپس صندوق خصوصی مدیر می‌رسند؛ این سرویس پایگاه داده یا ذخیره‌سازی گزارش ندارد.
- مسیر صفحه و زبان سایت همراه گزارش فرستاده می‌شوند؛ موقعیت جغرافیایی، نشانی مرورگر و تصویر صفحه خودکار جمع‌آوری نمی‌شوند. برای جلوگیری از هرزنامه، نشانی اتصال فقط به‌طور موقت در حافظهٔ همان فرایند برای محدودکردن تعداد درخواست‌ها به کار می‌رود و در گزارش ایمیل قرار نمی‌گیرد.
- محدودیت فعلی پنج درخواست در ساعت برای هر نشانی اتصال و یک خانهٔ پنهان ضدربات است. این دفاع پایه‌ای است، نه سامانهٔ مقابله با حملهٔ گسترده.

## آماده‌سازی Resend

برای این پیکربندی تک‌گیرنده، Resend می‌تواند با فرستندهٔ آزمایشی `onboarding@resend.dev` کار کند؛ طبق محدودیت Resend، آن فرستنده فقط به نشانی صاحب حساب Resend پیام می‌دهد. بنابراین حساب Resend را با همان نشانی خصوصی‌ای بسازید که در متغیر `REPORT_TO` قرار می‌گیرد. پس از تأیید حساب، یک کلید API با دسترسی ارسال ایمیل بسازید.

اگر بخواهید گزارش‌ها به نشانی دیگری هم فرستاده شوند یا فرستندهٔ اختصاصی داشته باشید، باید دامنهٔ خودتان را در Resend تأیید کنید و مقدار `REPORT_FROM` را به فرستندهٔ همان دامنه تغییر دهید. رمز جی‌میل را در Render یا این پروژه وارد نکنید.

## استقرار API در Render

1. فایل‌های پروژه را به مخزنی که خودتان به Render وصل می‌کنید اضافه کنید؛ من چیزی را commit، push یا مستقر نکرده‌ام.
2. راه ساده‌تر، استفاده از `render.yaml` در ریشهٔ پروژه است: در Render از **New → Blueprint** مخزن را وصل کنید. این فایل فقط یک Web Service با نام پیشنهادی `orbita-report-api` می‌سازد؛ سایت ایستای فعلی را جایگزین یا تغییر نمی‌دهد. اگر نام سرویس قبلاً گرفته شده باشد، نام دیگری انتخاب کنید.
3. اگر تنظیم دستی را ترجیح می‌دهید، یک **Web Service** بسازید و `report-api` را به‌عنوان **Root Directory** انتخاب کنید. دستورهای آماده در Blueprint چنین‌اند:
   - Build Command: `npm install`
   - Start Command: `npm start`
   - Health Check Path: `/api/health`
4. در زمان ساخت Blueprint یا در بخش Environment، این مقدارهای محرمانه/محیطی را تنظیم کنید:
   - `RESEND_API_KEY` — کلید محرمانهٔ Resend؛ فقط در پنل Render وارد شود.
   - `REPORT_TO` — نشانی صندوق خصوصی گزارش‌ها که کاربر تعیین کرده است.
   - `REPORT_ALLOWED_ORIGIN` — `https://orbita-site.onrender.com`
   - `REPORT_FROM` — Blueprint مقدار آزمایشی `ORBITA Reports <onboarding@resend.dev>` را می‌گذارد؛ برای استفاده از فرستندهٔ دیگری، دامنه باید در Resend تأیید شده باشد.
5. پس از ساخت سرویس، نشانی عمومی API معمولاً `https://orbita-report-api.onrender.com/api/report` خواهد بود. مقدار خالی `window.ORBITA_REPORT_API_URL` در ابتدای `index.html` را با نشانی واقعی جایگزین کنید. اگر نام سرویس عوض شده باشد، نشانی آن را وارد کنید. این نشانی عمومی است؛ کلید Resend را هرگز در HTML نگذارید.
6. پس از تنظیم نشانی API و متغیرها، سایت اصلی و سرویس API را با روش استقرار خودتان منتشر کنید و یک گزارش آزمایشی بفرستید. در پلن رایگان Render ممکن است سرویس پس از بی‌کاری موقتاً خوابیده باشد و نخستین درخواست دیرتر پاسخ دهد.

تا زمانی که نشانی API در `index.html` و متغیرهای محیطی در Render تنظیم نشده باشند، فرم با پیام روشن اعلام می‌کند که ارسال آماده نیست و گزارشی ارسال نمی‌شود.

## محلی

در این پوشه اجرا کنید:

```sh
npm test
npm start
```

برای ارسال واقعی، علاوه بر متغیرهای لازم در محیط، باید یک API URL در سمت سایت و یک نشانی مجاز در `REPORT_ALLOWED_ORIGIN` تنظیم شود. هیچ کلید یا نشانی خصوصی را داخل فایل‌های مرورگر قرار ندهید.
