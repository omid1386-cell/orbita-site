# قرارداد داده بانک رسانه ORBITA — نسخه ۱

## شناسه و ارتباط با شناسنامه

کلید هر المان از `entity_type:category:entity_id` ساخته می‌شود. این روش با شناسه‌های موجود در `data/companies.json`، `data/sites.json` و `data/recovery_sites.json` سازگار است:

- سازمان/شرکت: `company_or_organization:agency:nasa`
- پایگاه پرتاب: `launch_site:launch_site:ksc39a`
- محل فرود: `recovery_site:recovery_site:recovery-lz4`

رابط نقشه در کد فعلی از مقادیر `site`، `recovery` و نام دسته شرکت استفاده می‌کند. تابع `keyFor(cat,id)` در `assets/js/media-bank.js` این ورودی‌ها را به کلید بانک تبدیل می‌کند. **شناسه رکوردهای اصلی تغییر نمی‌کند.**

## ساختار پوشش همه ۴۲۰ رکورد

در `data/media/catalog.v1.json` برای تمام المان‌ها `entity_key`، نام فارسی و انگلیسی، مرجع داده، `review_status`، `legacy_media` و آرایه مستقل `media` تعریف شده است. در این مرحله همه آرایه‌های `media` خالی هستند و تنها برای گردآوری در گام‌های بعد آماده‌اند.

`legacy_media` فقط وضعیت قبلی را گزارش می‌کند؛ `profile_photo`، `gallery_count` و `event_video_link_count` نباید به طور خودکار «رسانه معتبر و دارای حق انتشار» قلمداد شوند. به‌ویژه تصاویر اصلی پایگاه‌های پرتاب بدون تغییر می‌مانند.

## فیلدهای رسانه

| فیلد | معنی |
|---|---|
| `media_id` | شناسه یکتای جهانی برای یک عکس/ویدئو در بانک، با پیشوند `med-` |
| `kind` | `image` یا `video` |
| `role` | نوع ارتباط با المان: تأسیسات، عملیات، محصول، مأموریت، پرتاب، فرود، تجهیزات، تاریخی و ... |
| `file_path` / `external_url` | دقیقاً یکی؛ فایل محلی از `assets/media/` یا پیوند HTTPS |
| `caption` | عنوان رسانه به فارسی، انگلیسی و در صورت امکان عربی |
| `alt` | متن دسترس‌پذیری تصویر به زبان‌های مختلف (اختیاری) |
| `captured_on` | تاریخ ثبت تصویر/ویدئو، **در صورت احراز** |
| `width`, `height`, `duration_seconds`, `sort_order` | مشخصات اختیاری؛ برای بهینه‌سازی و نمایش در گام ۳ |
| `thumbnail_path` | تصویر بندانگشتی محلی در `assets/media/` |
| `file_sha256` | هش فایل ذخیره‌شده (اختیاری) |
| `source.url` و `source.publisher` | نشانی منبع اصلی و ناشر |
| `rights.usage` | وضعیت مجوز: نامشخص، عمومی، مجاز، با انتساب، فقط پیوند یا محدود |
| `rights.credit`, `rights.license`, `rights.proof_url`, `rights.checked_on` | صاحب اثر، مجوز، دلیل حقوقی و تاریخ کنترل |
| `verification.status` | `candidate`، `verified` یا `rejected` |
| `verification.identity_match` | تطبیق هویت تصویر با المان: بررسی‌نشده، تأییدشده یا ردشده |
| `verification.source_verified` | بررسی واقعی نشانی و هویت منبع توسط ویراستار |
| `verification.reviewed_on`, `reviewer` | تاریخ و فرد مسئول بازبینی |

## قواعد قطعی انتشار

در گام ۳ فقط رسانه‌ای به رابط کاربر راه می‌یابد که:

1. وضعیت `verified` داشته باشد؛ هویت بصری و اعتبار منبع هر دو تأیید شده باشند.
2. مجوز آن معتبر و بررسی‌شده باشد؛ مورد `restricted` یا `undetermined` نمایش داده نشود.
3. `reviewer` و تاریخ بررسی منبع و مجوز ثبت شده باشد.
4. عکسِ با مجوز «فقط پیوند» داخل سایت نمایش داده نشود؛ ویدئوی `link_only` صرفاً به صفحه منبع لینک شود، نه اینکه بدون مجوز در قاب سایت پخش گردد.
5. برای استفاده با انتساب، نام صاحب اثر و نوع مجوز ثبت شده باشد؛ برای اجازه صریح سند/پیوند مجوز لازم است.
6. کد رابط در مرحله بعد عنوان‌ها و توضیحات را HTML-escape کند و به‌هیچ‌وجه متن قابل‌اعتماد فرض نکند.

نشانی و مجوز «نمونه» داخل `docs/EXAMPLE_MEDIA_CANDIDATE_DO_NOT_PUBLISH.json` ساختگی است؛ آن فایل نباید به عنوان رسانه واقعی ثبت یا نمایش داده شود.

## سازگاری نسخه و خطاها

نسخه قرارداد `1.0.0` است. نسخه ناشناخته باید باعث عدم نمایش رسانه‌های جدید شود، نه خراب‌شدن شناسنامه‌ها. ماژول مرورگر تنها هنگام درخواست صریح `load()` فایل را می‌گیرد و اگر اتصال قطع باشد امکان تلاش مجدد دارد. وضعیت پرونده‌های قبلی صرفاً در داده موجود حفظ می‌شود.
