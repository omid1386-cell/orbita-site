# ORBITA — ممیزی دریافت و اعتبارسنجی داده زنده جهانی

**تاریخ بررسی:** ۲۱ نوامبر ۲۰۲۶  
**دامنه:** پرتاب‌ها و فرودهای ۱۲۰ روز آینده؛ بسته نامزد انتشار گام نهم RC1.  
**وضعیت:** بررسی ساختار منبع و آزمون‌های آفلاین تکمیل؛ **دریافت کامل زنده و تأیید سراسری انجام نشده است.**

## جمع‌بندی مدیریتی

| سنجه | نتیجه | توضیح |
|---|---|---|
| دسترسی به LL2 v2.3 از مسیر جست‌وجوی وب | پاسخ معتبر API مشاهده شد | صفحات رسمی پرتاب و فرود HTTP 200 نشان می‌دهند |
| دریافت مستقیم زنده از محیط اجرای کد | ناموفق | DNS سرویس از این محیط resolve نمی‌شود (`Temporary failure in name resolution`) |
| همگام‌سازی پرتاب‌های جهانی در فایل بسته نهایی RC1 | انجام‌نشده | `awaiting_first_successful_sync`، صفر رکورد در snapshot جدید |
| همگام‌سازی فرودهای جهانی در فایل بسته نهایی RC1 | انجام‌نشده | `awaiting_first_successful_sync`، صفر رکورد در snapshot جدید |
| بررسی فرم پاسخ واقعی پرتاب | انجام‌شده | pad.country و pad.location.country به‌صورت آبجکت؛ اپراتور در حالت normal به‌صورت خلاصه |
| بررسی فرم پاسخ واقعی فرود | انجام‌شده | country در landing_location.location؛ نبود فیلتر تاریخ فرود |
| پوشش کامل ۱۲۰ روزه در محیط اجرا | **تأیید نشده** | بدون خواندن همه صفحه‌ها و آزمون تطبیق نمی‌توان ادعا کرد |
| آزمون قرارداد پاسخ با نمونه‌های ساختاری | ۷ از ۷ موفق | تست محلی؛ جایگزین فراخوانی واقعی API نیست |
| آزمون JS فیلتر پرتاب‌ها و فرودها | موفق | ۱۳ کنترل پرتاب، ۱۰ کنترل فرود، و ۵ آزمون یکپارچگی Node |

## یافته‌های اصلی

۱. **ایراد کشور محل پرتاب در RC1:** کد مقدار `location.country_code` را می‌خوانْد، اما منبع LL2 در پاسخ نمونه مقدار کشور را در `pad.country.alpha_3_code` یا `pad.location.country.alpha_3_code` ارائه می‌کند. نتیجه احتمالی: نمایش «نامشخص» یا خروجی خالی هنگام انتخاب کشور پایگاه.

۲. **ایراد کشور اپراتور در RC1:** شیء `launch_service_provider` در پاسخ `mode=normal` معمولاً شناسه و نام را دارد، نه `country_code`. کشور در شناسنامه خود آژانس به‌صورت آرایه `country` موجود است. بنابراین استفاده از حالت `mode=detailed` و خواندن ساختار کشور پیشنهاد و در نسخه اصلاحی اضافه شد. **وجود این فیلد در تمام پاسخ‌های detailed آینده در محیط اجرای مستقیم هنوز تأیید نشده است.** نگهبان کیفیت برای جلوگیری از انتشار فیلتر ناقص ایجاد شده است.

۳. **محدودیت داده فرودها:** endpoint `landings/` دارای فیلتر عمومی تاریخ برنامه فرود نیست. این endpoint تاریخچه و برخی تلاش‌های برنامه‌ریزی‌شده را یکجا نگه می‌دارد. همچنین پاسخ normal در برخی رکوردها پیوند مستقیم `firststage.rocket.launch` ندارد. استخراج تاریخ فرود باید تنها از شواهد قابل‌دفاع انجام شود؛ تاریخ پرتاب جایگزین ساعت فرود نیست. **پوشش جهانی فرودها در وضعیت «جزئی» باقی می‌ماند.**

۴. **شمارش پاسخ‌های نمونه:** نمونه رسمی API در زمان مشاهده، `count=475` را برای کل فهرست upcoming launches و `count=1797` برای کل فهرست landings گزارش می‌کند. **این دو عدد شمار رویدادهای ۱۲۰ روز آینده نیستند** و نباید به‌عنوان موجودی ORBITA یا پوشش تأییدشده اعلام شوند.

۵. **سهمیه دریافت:** طبق مستندات منبع، استفاده بدون کلید API حداکثر ۱۵ درخواست در ساعت است. اجرای آزمون پرتاب و فرود باید در ساعت‌های جداگانه انجام شود تا از عبور تصادفی از محدودیت جلوگیری شود.

## اصلاحات ساخته‌شده در نسخه کاری (منتشر نشده)

- افزودن `tools/ll2_country.py`: خواندن بدون حدس کشور در قالب آبجکت، آرایه یا کد صریح.
- اصلاح `tools/refresh_global_launches.py`: خواندن کشور پایگاه از ساختار واقعی و درخواست `mode=detailed` برای دریافت احتمالی وابستگی اپراتور.
- افزودن نگهبان کیفیت: اگر کمتر از ۸۵٪ از رکوردهای دارای اپراتور/پایگاه کد کشور معتبر داشته باشند، snapshot جدید منتشر نمی‌شود.
- افزودن شاخص `country_quality` در گزارش snapshot، شامل تعداد کدهای شناخته‌شده و تعداد کل رکوردهای نیازمند کشور.
- اصلاح برداشت کشور در `tools/refresh_global_landings.py`.
- اصلاح داده آزمایشی `tools/test_global_launches.py` تا با ساختار nested واقعی هماهنگ شود.
- افزودن ۷ آزمون قرارداد در `tools/test_live_source_contract.py`.
- افزودن ابزار فقط‌خواندنی `tools/validate_live_global_sources.py` که کد اتصال واقعی را اجرا و نتیجه را در JSON ثبت می‌کند.

**توجه:** تغییر `mode=detailed` و آستانه کیفیت، هنوز به دریافت زنده معتبر از محیط دارای اینترنت نیاز دارند. این نسخه برای آزمون شبکه‌ای آماده شده، نه تأیید نهایی انتشار عمومی.

## شواهد اجرای فعلی

- آزمون‌های قرارداد پاسخ واقعی‌نما: **۷/۷ موفق**.
- آزمون Node فیلتر پرتاب‌ها: **۱۳ کنترل موفق**.
- آزمون Node فیلتر فرودها: **۱۰ کنترل موفق**.
- آزمون یکپارچگی گام ۸: **۵ آزمون موفق**.
- بررسی نمونه انتخاب همزمان CHN و USA در موتور JS: **موفق**.
- `python tools/refresh_global_launches.py`: خروجی `ERROR — no data changed: <urlopen error [Errno -3] Temporary failure in name resolution>`.
- آزمون مستقیم منبع فرود با داده‌های کمکی خالی برای پرهیز از فقدان فایل‌های legacy در بسته کوچک: **همان خطای DNS**.
- هیچ رکورد زنده جدید به `data/upcoming_global.json` یا `data/upcoming_global_landings.json` اضافه نشده است.

## روش تکمیل مرحله زنده، بدون انتشار اپ

دستورها فقط در **سورس کامل ORBITA** و در محیطی با اتصال HTTPS به `ll.thespacedevs.com` اجرا شوند:

```bash
# ساعت اول؛ فقط بررسی کامل دریافت پرتاب‌ها، بدون ذخیره snapshot
python tools/validate_live_global_sources.py --launch-only --report launch_live_check.json

# در ساعت دیگری از سهمیه API؛ فقط بررسی فرودها، بدون تغییر برنامه
python tools/validate_live_global_sources.py --landing-only --report landing_live_check.json
```

شرط موفقیت مرحله پرتاب: دریافت تمام صفحات بازه ۱۲۰ روزه، شناسه‌های غیرتکراری، تاریخ‌های معتبر، وضعیت درست `country_quality` و نبود خطای قرارداد. **شرط موفقیت مرحله فرود** صرفاً تأیید سلامت دریافت جزئی همراه با اعلام روشن شکاف پوشش، نه ادعای استخراج تمامی فرودهای جهان.

## وضعیت انتشار

**هیچ تغییر، Commit، Push یا Deploy انجام نشد.** آزمون واقعی برنامه پس از انتشار عمداً برای مرحله بعدی حفظ شده است. افزون بر آن، رفع مشکل شبکه برای دریافت زنده از اجرای فعلی و سپس اجرای آزمایش بالا در محیط دارای اینترنت هنوز لازم است.
